## 修复目标
在**不改变现有功能**的前提下,修复对未提交重构(巨型 Service 拆分)的审查发现的问题,并连同恢复被删除的熔断逻辑测试。所有修复以 HEAD(提交 0cdc904 之前的版本)行为为基线对齐。

## 一、严重回归:reloadModels 破坏性操作(问题 1+5)

现状:`ChannelModelQuery.reloadModels` 调用 `modelLoader.loadModels(channel, null)`,而 `channels.api_key` 列已废弃(update.sql:189),DB 加载出的 key 为空 → 拉取失败 → 兜底预设默认模型,但 loadModels 开头仍会删光 `source='api'` 真实模型(ChannelModelQuery.java:62-68)。该路径同时被 AdminChannelController.java:234 和定时任务 ChannelModelRefreshTask.java:82 调用,影响大。

- `ChannelModelQuery.reloadModels`:改调 `modelLoader.loadModelsForChannel(channel)`,补 `@Transactional`(HEAD 原有)。
- `ChannelModelLoader.loadModelsForChannel`(L72-83):`channelApiKeyMapper.selectAllByChannelId` → `selectEnabledByChannelId`(恢复 HEAD 的"第一个**启用** key"语义,方法已在 ChannelApiKeyMapper.java:23),补 `@Transactional`。
- `ChannelModelLoader.loadModels(Channel,String)`(L88):补 `@Transactional`(HEAD L343-344 原有,覆盖删除+拉取+插入整段)。

## 二、写路径缓存失效丢失 + 命名空间字面量(问题 2)

读写 namespace 统一为当前读方字面量值(常量目前无引用,改值零行为影响):

- `LocalCacheService.java:47-50`:4 个常量值改为现字面量:`NS_MODEL_BY_ID="model_by_id"`、`NS_MODEL_BY_NAME="model_by_name"`、`NS_CHANNEL_MODEL_BY_ID="channel_model_by_id"`、`NS_CHANNEL_BY_ID="channel_by_id"`;`NS_API_KEY_BY_CHANNEL`/`NS_CIRCUIT_STATE_BY_SCOPE` 不动。
- `ModelCrud.java`(5 处)、`ModelCacheQuery.java`(4 处)、`ModelService.java:228`:字面量改用上述常量(消除常量死代码)。
- `ChannelService` 门面复用现有可选字段 `localCacheService` + `hasCache()`,按 HEAD 逐点恢复失效(9 处,均在子组件调用成功后执行、带 null 防护):
  - `update` → invalidate(channel_by_id, channel.getId())
  - `create` → invalidateAll(channel_model_by_id)(对应 HEAD create→loadModels 链路)
  - `updateWithModels` → invalidate(channel_by_id, id) + invalidateAll(channel_model_by_id)
  - `delete` → invalidate(channel_by_id, id) + invalidateAll(channel_model_by_id)
  - `loadModels` / `reloadModels` / `createWithManualModels` / `deleteAllChannelModels` → invalidateAll(channel_model_by_id)
  - `addManualModel` → invalidate(channel_model_by_id, cm.getId());`deleteChannelModel` → invalidate(channel_model_by_id, modelId)
- 与读方对齐:ModelCacheQuery.getChannelById、ModelService.getChannelModelById(localCacheService.get(L227))写后立即获取最新值;5 秒 TTL 作为兜底不变。
